## 2025-02-05 - Missing Accessible Names on Responsive Icon Buttons
**Learning:** When using responsive utility classes (like `hidden lg:inline` in Tailwind) to hide text labels on smaller screens, interactive elements like `<button>` and `<a>` lose their accessible name on those viewports if they only contain an icon (e.g., Material Symbols). This causes screen readers to read the raw icon ligature (e.g., "rocket launch" or "content copy") instead of the intended action, or read nothing at all if the icon is hidden from assistive technologies without providing an alternative. Additionally, raw icon ligatures should be hidden from screen readers using `aria-hidden="true"` to prevent them from being announced when an explicit accessible name is provided.
**Action:** Always ensure that interactive elements have a definitive, viewport-independent accessible name. Use `aria-label` on the parent `<button>` or `<a>` and add `aria-hidden="true"` to the inner icon element (e.g., `<span class="material-symbols-outlined">`). This guarantees that regardless of visual presentation (whether text is visible or hidden via CSS), the control's purpose is consistently and accurately announced to assistive technologies.
