## 2026-02-23 - Screen Reader Accessibility with Responsive Tailwind Classes
**Learning:** When using responsive utility classes (like `hidden lg:inline`) to hide text on smaller viewports, interactive elements (such as links or buttons) become functionally unlabelled to screen readers on those smaller screens because the visible text is completely removed from the DOM or hidden. Furthermore, icon ligatures (e.g. `<span class="material-symbols-outlined">arrow_back</span>`) are read out loud as text ("arrow back") which can be confusing or redundant.
**Action:** Always add an explicit `aria-label` to the parent interactive element (`<button>` or `<a>`) to ensure a consistent, accessible name across all viewports. In tandem, always apply `aria-hidden="true"` to structural icon elements to prevent screen readers from reading raw ligatures, provided the parent element has an accessible name.
